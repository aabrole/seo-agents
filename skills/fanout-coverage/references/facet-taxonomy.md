# Facet Taxonomy

Classify every observed sub-question into one facet. The point is to see the *shape* of the gap: a site with 20 Owned rows that are all Definitional has no commercial coverage at all, and a flat list hides that.

## The facets

| Facet | The sub-question is asking | Typical phrasing |
|---|---|---|
| **Definitional** | what the thing is | what is X, X meaning, how X works |
| **Comparative** | X against a named alternative | X vs Y, X or Y, difference between |
| **Evaluative** | which option is best under a condition | best X for Y, top X, X recommendations |
| **Qualifying** | whether it applies to me | is X right for, do I need X, who should use X |
| **Cost** | price, what drives it, what is included | X pricing, how much does X cost, X fees |
| **Constraint** | fit against a hard limit | X for small teams, X for HIPAA, X under $50, X without Z |
| **Procedural** | how to do it | how to X, X setup, steps to X |
| **Troubleshooting** | why it broke and how to fix it | X not working, X error, why does X |
| **Temporal** | how long, when, what changed | how long does X take, X in 2026, is X still |
| **Trust** | proof, risk, credibility | is X safe, X reviews, X legit, X risks |
| **Local** | geography-bound | X near me, X in [city], X [state] rules |
| **Alternative** | what to use instead | X alternatives, instead of X, replace X |

## How to use it

**In Step 1**, tag each observed sub-question. Do not force a fit, a sub-question that lands in two facets is usually two sub-questions.

**In Step 2**, count Owned versus Missing per facet. Facet-level holes are the real finding. Common patterns:

- All Definitional coverage, no Cost or Constraint: the site ranks for research intent and gets cited for nothing that converts.
- Comparative missing entirely: competitors own every "X vs Y" branch and the client is invisible at the decision point.
- Constraint missing: the highest-value branches, because constraint sub-questions are where a small site beats an incumbent. The head term is unwinnable, "X for a 4-person team on QuickBooks Desktop" is not.
- Troubleshooting missing: no retention or support surface, and support content is disproportionately cited because it is concrete.

**Mapping to page structure.** Most facets belong as blocks on an existing page. These usually justify their own page:

- Comparative (one page per named competitor pair)
- Alternative (one page per competitor)
- Evaluative when the qualifier is commercially distinct
- Local when the geography has genuinely different content, not a spun template
- Constraint when the constraint defines a real segment with its own buying process

These almost never justify their own page and belong as blocks: Definitional, Cost (belongs on the pricing page), Qualifying, Temporal, Trust.

Procedural and Troubleshooting depend on volume: one page per distinct task or error, but never one per phrasing variant.

## The redundancy test

Before creating anything for a sub-question, ask: **does the answer differ from the sibling branch, or only the wording?** Diversity scoring in fan-out generation explicitly pushes away from synonym restatements, so two sub-questions with the same answer collapse into one branch and one page. Two sub-questions with different answers are two branches worth serving separately.

If you cannot state in one sentence how the answer differs, it is one branch.
