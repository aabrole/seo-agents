# CORE-EEAT Content Checklist (80 Items)

> Adapted from aaron-he-zhu's `core-eeat-content-benchmark` v3.0. Full source: https://github.com/aaron-he-zhu/core-eeat-content-benchmark

## Framework

**8 dimensions × 10 items = 80 evaluation criteria** for AI-engine and search-engine content quality.

### Two-system architecture

| System | Focus | Dimensions | Boundary |
|---|---|---|---|
| CORE | GEO (AI engine optimization) | C, O, R, E | Content body |
| EEAT | SEO (search engine optimization) | Exp, Ept, A, T | Author / org / site credibility |

**MECE boundary rule:** CORE evaluates the content itself. EEAT evaluates the source. No overlap.

### Priority tags

- 🎯 **GEO-First** — critical for AI engine citation
- 🔍 **SEO-First** — critical for traditional search ranking
- ⚡ **Dual** — important for both

## CORE dimensions (40 items) — content body

### C — Contextual Clarity (does the content answer user intent?)

| ID | Item | Priority | Standard |
|---|---|---|---|
| C01 | Intent Alignment | ⚡ | Title promise = content delivery |
| C02 | Direct Answer | 🎯 | Core answer in first 150 words |
| C03 | Query Coverage | ⚡ | Covers ≥3 query variants (synonyms, long-tail) |
| C04 | Definition First | 🎯 | Key terms defined on first use |
| C05 | Topic Scope | 🎯 | Explicitly states what is and isn't covered |
| C06 | Audience Targeting | ⚡ | States "this article is for..." |
| C07 | Semantic Coherence | 🎯 | Logical flow between paragraphs, no jumps |
| C08 | Use Case Mapping | 🎯 | Decision framework: when to choose A vs B |
| C09 | FAQ Coverage | 🎯 | Structured FAQ covering long-tail follow-ups |
| C10 | Semantic Closure | ⚡ | Conclusion answers the opening question + next steps |

### O — Organization (structured for humans AND machines?)

| ID | Item | Priority | Standard |
|---|---|---|---|
| O01 | Heading Hierarchy | ⚡ | H1→H2→H3, no level skipping |
| O02 | Summary Box | 🎯 | Has TL;DR or Key Takeaways section |
| O03 | Data Tables | 🎯 | Comparisons and specs in tables |
| O04 | List Formatting | 🎯 | Parallel items use bullet/numbered lists |
| O05 | Schema Markup | 🎯 | Appropriate JSON-LD (Article/FAQ/HowTo/etc.) |
| O06 | Section Chunking | 🎯 | Each section has single topic; paragraphs 3-5 sentences |
| O07 | Visual Hierarchy | 🔍 | Key concepts bolded or highlighted |
| O08 | Anchor Navigation | ⚡ | Table of contents with jump links |
| O09 | Information Density | 🎯 | No filler; consistent terminology |
| O10 | Multimedia Structure | ⚡ | Images/videos have captions and carry information |

### R — Referenceability (can AI/readers verify and cite claims?)

| ID | Item | Priority | Standard |
|---|---|---|---|
| R01 | Data Precision | 🎯 | ≥5 precise numbers with units (%, $, ms) |
| R02 | Citation Density | 🎯 | ≥1 external citation per 500 words |
| R03 | Source Hierarchy | 🎯 | Primary sources first; ≥3 Tier 1-2 sources |
| R04 | Evidence-Claim Mapping | 🎯 | Every claim backed by evidence immediately after |
| R05 | Methodology Transparency | 🎯 | Sample size, steps, criteria documented |
| R06 | Timestamp & Versioning | ⚡ | Last updated <1 year; version changes noted |
| R07 | Entity Precision | 🎯 | Full names for people/orgs/products; no "a company" |
| R08 | Internal Link Graph | 🔍 | Descriptive anchor text forming topic clusters |
| R09 | HTML Semantics | 🎯 | Uses `<article>`, `<figure>`, `<time>`, `<cite>` |
| R10 | Content Consistency | ⚡ | Data self-consistent; no broken links |

### E — Exclusivity (content unavailable elsewhere?)

| ID | Item | Priority | Standard |
|---|---|---|---|
| E01 | Original Data | 🎯 | First-party research, surveys, proprietary datasets |
| E02 | Unique Framework | 🎯 | Named methodology or taxonomy not found elsewhere |
| E03 | Case Studies | 🎯 | Specific named outcomes with measurable results |
| E04 | Insider Perspective | 🎯 | Experience-based insights, not just theory |
| E05 | Counter-Intuitive Claims | 🎯 | Challenges assumptions with evidence |
| E06 | Quantified Outcomes | 🎯 | Results expressed in specific numbers |
| E07 | Named Examples | 🎯 | Real companies/people/products (not generic) |
| E08 | Custom Visualizations | ⚡ | Charts, diagrams created for this content |
| E09 | Expert Quotes | 🎯 | Direct quotations from named authorities |
| E10 | Comparative Analysis | 🎯 | Side-by-side with ≥3 alternatives |

## EEAT dimensions (40 items) — source credibility

## Scoring

### Lightweight mode (default — 20 items)

Use this subset for standard audits. Each item: pass / partial / fail (2 / 1 / 0 points). Max score 40, normalized to 100.

**Lightweight core items:**
- CORE: C01, C02, C04, C09, O01, O02, O05, R01, R02, R06, R07, E01
- EEAT: A01, A05, A07, T01, T02, T05, Exp01, Ept01

### Full mode (all 80 items)

For deep audits. Same 0/1/2 scoring, max 160, normalized to 100.

### Score interpretation

| Score | Rating |
|---|---|
| 90-100 | Exemplary content quality and source credibility |
| 75-89 | Strong content with minor gaps |
| 60-74 | Meets baseline but significant optimization possible |
| 40-59 | Substantial content/credibility weaknesses |
| 0-39 | Content/credibility issues likely preventing citation |

## Usage notes

- For a quick audit, sample 3-5 high-value pages, apply lightweight mode
- For a deep audit, sample 10-20 pages, apply full mode
- EEAT items are typically site-wide — evaluate once per domain, not per page
- CORE items are per-page — evaluate on each sampled page, average scores
